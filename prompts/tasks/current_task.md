# 普通用户 AI 额度配置与 AI 系统栏目修复计划

更新日期：2026-11-23（Asia/Shanghai）。调研基线：本地 `main`，`f1099696`。

**状态：已完成 Mill 的只读审查及计划修订；本轮仅提交计划文件。以下业务实现、实现测试、迁移、部署和账号配置均未执行。**

## 1. 本次目标与边界

1. 把普通用户的 AI 防滥用配置统一放到 `/app-users`，同时提供全局默认值、单用户覆盖和指定账号无限制。
2. 调研 `/ai-settings?tab=system` 的真实作用，修复范围表述、月度计量、配置执行与页面反馈问题。
3. 两项任务共享明确的领域边界：普通用户学习 AI 策略属于 `/app-users`；后台导题／补全的运行控制属于 AI 设置。普通用户默认额度不再在两个页面重复维护。
4. 本轮授权为请 Mill 审查本任务规划、修订并提交计划文件。后续业务实现须另行获得执行指令；本计划不授权修改生产配置、给任何账号开特权、迁移、发布或付费调用 LLM。
5. 不引入新网关、计费平台或额外依赖；优先复用既有 Redis 原子缓存、Token 预占／结算、Admin RBAC、审计、目录页和表单组件。

## 2. 调研结论与证据

### 2.1 普通用户防滥用限制的现状

| 已核实事实 | 当前实现 | 对计划的影响 |
| --- | --- | --- |
| 错题复盘重新生成的次数和冷却时间写在业务代码中 | `backend/app/services/ai/analysis_regeneration.py`：账号 60 秒内 1 次、同题滚动 24 小时 3 次、账号滚动 24 小时 20 次 | 需要动态策略，不能只新增前端输入框 |
| 同题识别使用稳定的题目 ID | 同上，按 `wrong_question.question_id` 计数 | 删除并重新加入错题不能重置额度，迁移后继续保留此语义 |
| 后台恢复请求还有独立的入队保护 | 同上，3 次／分钟、30 次／小时；实际生成另走生成限额 | 区分付费调用额度和队列保护，避免开无限后产生重复入队 |
| 普通用户每日／每月 Token 预算来自运行配置 | `backend/app/services/ai_token_budget.py:41` 的 `reserve_token_budget` | 只解除重新生成次数，仍可能被 Token 预算阻止 |
| 还有直接读取旧 Token 配置的检查入口 | `backend/app/services/ai_learning_service.py:93` 的 `check_token_limit` | 预检查和实际预占必须使用同一份有效策略 |
| 通用 AI 网关还有用户 RPM | `backend/app/core/ai_runtime_guard.py:196` 的 `enforce_rate_limit` | 指定账号的无限模式要覆盖普通用户 RPM，不能留下隐性配额 |
| `/app-users` 已有普通用户目录、详情、筛选和 Admin API | `admin-frontend/src/app/(admin)/app-users/page.tsx`；`backend/app/api/v1/admin_app_users.py` | 在现有页面增加配置入口，按需查询，不重做用户管理 |

每日／每月 Token 和通用 RPM 的**生产实际值本次未读取**；实施时要核对运行配置后再初始化数据库默认策略。重新生成的 60 秒／3 次／20 次来自当前源码。

## 3. 任务 A：在 `/app-users` 配置普通用户 AI 额度

### A1. 定义策略契约与数据归属（P0）

- [ ] 新增独立的普通用户 AI 策略模型、schema 和服务，建议采用“一份全局默认策略 + 每用户至多一份覆盖”的关系模型；复用 `users` 主体和 Admin 操作者外键。
- [ ] 不把普通用户策略塞入 `AdminAISettings`，不把权限写入昵称／备注字段，不用邮箱、openid、硬编码 user ID 或 Admin 角色判断谁享有特权。
- [ ] 为覆盖值定义明确的三态：**继承默认／有限值／不限**。API 返回原始覆盖、全局默认、最终有效值及逐字段来源；不能混用缺省、`null`、`0` 表达多个含义。
- [ ] 建议覆盖字段如下；最终字段命名在接口评审时固定，数值一律由后端校验：

| 维度 | 全局初始化语义 | 用户覆盖能力 |
| --- | --- | --- |
| 复盘重新生成冷却时间 | 保持现有 60 秒 | 继承／指定秒数／无冷却 |
| 同题滚动 24 小时重新生成次数 | 保持现有 3 次 | 继承／指定次数／不限 |
| 账号滚动 24 小时重新生成次数 | 保持现有 20 次 | 继承／指定次数／不限 |
| 普通用户 AI 每日 Token 预算 | 取部署环境现有有效值 | 继承／指定 Token 数／不限 |
| 普通用户 AI 每月 Token 预算 | 取部署环境现有有效值 | 继承／指定 Token 数／不限 |
| 普通用户通用 AI RPM | 取部署环境现有有效值 | 继承／指定次数／不限 |

- [ ] 页面提供“一键设为无限制”，将上述用户维度显式设为不限；“恢复默认”删除覆盖并重新继承。不限不代表禁用 AI，也不依赖将限额设为极大整数。
- [ ] 明确 Token 与通用 RPM 属于该普通用户的学习 AI 调用范围，重新生成三项只影响错题复盘重新生成；不改变后台管理员导题预算。
- [ ] 并发、同题在途锁、幂等、队列去重、恢复入队保护、超时、熔断、模型可用性等属于运行保护，不随个人不限关闭；界面明确“不限额度，仍受系统运行保护”。
- [ ] 不用普通用户与管理员的绑定关系自动开通额度，不改变现有身份域、封禁或鉴权规则。

### A2. 数据迁移与唯一生效来源（P0）

- [ ] 通过 Alembic 创建策略表、用户覆盖唯一约束、配置版本和必要审计元数据；不改动已有模型配置表及模型 ID。
- [ ] 首次初始化保持既有限额；重新生成默认值按现有源码，Token／RPM 采用受控初始化读取实际运行配置，不在通用迁移中猜测生产环境变量。
- [ ] 初始化后数据库是动态策略的唯一管理来源；旧环境变量仅作为已定义的首次初始化／兼容回退来源，不与数据库长期双写。显式“不限”不得被回退默认值重新覆盖。
- [ ] 用版本号／条件更新防止两名管理员互相覆盖；全局默认变更只影响继承项，用户显式覆盖不变。
- [ ] 普通请求按用户解析一次有效策略；同步调用与 worker 恢复共用解析服务，避免各层自行拼接默认值。
- [ ] 配置缓存使用共享版本或可靠失效机制，确保 Web 多进程和 worker 在下一次准入使用同一新版本；在途请求保留已获取的准入／结算快照，不因保存配置中途改变账单。
- [ ] 配置或 Redis 故障时维持既有保守拒绝语义，不能把读取失败解释为不限；本地无 Redis 的 fallback 只用于既有开发模式。

### B2. 恢复可信的月度计量与准入（P0）

## 6. 验证计划与验收标准

### 6.1 后端／数据／并发

- [ ] 默认 60 秒／3 次／20 次行为兼容；滚动 24 小时边界、跨日不重置、删错题重建不能绕过。

- [ ] 原子并发测试证明剩余额度只有一次时最多一次获准；真实隔离 Redis 验证多进程／worker 共享；配置故障和 Redis 故障不会放开限制。
